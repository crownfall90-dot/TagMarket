# TagMarkets — ревью и план исправлений

Начато 16 сентября, обновлено 17 сентября 2026. Область: бот, агент MT5, webhook API, хранилище,
служебные скрипты, макеты и новое Telegram Mini App. Проверены исходники,
регрессионные тесты, браузерный интерфейс и доступное состояние VPS.
Это список обнаруженных проблем, а не заявление об отсутствии остальных.

Приоритеты: P0 — доступ/целостность данных; P1 — неверные результаты или отказ
основного сценария; P2 — функциональные, UX и эксплуатационные проблемы;
P3 — улучшение сопровождения. `[x]` означает исправление в коде; состояние
установки на работающих машинах описывается отдельно в конце файла.

## Исправлено в этой задаче

- [x] **P1 / HA-01 — две машины одновременно опрашивали MT5.**
  `agent.py:main`: флаг `took_over` навсегда включал резерв до перезапуска,
  primary при возвращении продолжал работать без координации.
  `webhook_server.py:agent_sync` записывал последнего отправителя как
  `active_machine`. Отсюда постоянные A → B → A и конкурирующие логины.
  Добавлены серверная аренда права опроса, идентификатор процесса,
  проверка перед каждым счётом и отклонение загрузок потерявшего право агента.
  Аренду продлевает только успешная загрузка, а не heartbeat. Проверено
  возвращение основной машины, истечение аренды, старые сессии и отказ MT5.
- [x] **P1 / DATA-01 — потеря параллельных изменений счетов.**
  Атомарный `os.replace` в `accounts.save` защищал файл от обрыва, но не
  транзакцию read-modify-write между ботом и новым API. Добавлена общая
  межпроцессная блокировка в `account_lock.py`; мутации выполняются под ней.
  Прямая перезапись всех счетов в `bot.py:cfg_base_set` заменена `accounts.update`.
- [x] **P1 / AUTH-01 — пустой WEBHOOK_TOKEN мог совпасть с отсутствующим
  заголовком.** `webhook_server.py:check_token` теперь отвергает пустую настройку.
- [x] **P1 / MINI-01 — вместо мини-приложения существовали только макеты.**
  Реализованы `miniapp.py`, `web/index.html`, `web/app.js`, `web/style.css`:
  HMAC-проверка Telegram initData, срок сессии, проверка доступа на каждом
  запросе, изоляция владельцев, API счетов/отчётов/гостей/настроек, общий
  источник данных с ботом, обновление каждые 15 секунд.
- [x] **P0 / MINI-02 — нельзя выдавать существующую историю только по
  введённому номеру MT5.** Новый API запрещает присвоить уже известный логин
  с произвольным паролем; доступ к существующему счёту — через приглашение.
  Повторное подключение оставшейся в БД истории требует владельца сервиса.
  Старый сценарий бота также исправлен — см. AUTH-02 ниже.
- [x] **P1 / MINI-03 — демо могло быть спутано с личным капиталом.**
  В мини-приложении отдельная карточка, явная метка наблюдения, исключение
  из личных итогов, запрет удаления/правки капитала демо через API.
- [x] **P1 / MINI-04 — неоднозначные суммы разных валют.**
  Mini App группирует личные итоги по валюте, без фиктивной конвертации.
- [x] **P1 / MINI-05 — точный диапазон внутри архивного месяца нельзя
  восстановить из месячной суммы.** API отвергает такой запрос с объяснением,
  вместо выдачи полного месяца за результат выбранных дней.
- [x] **P2 / UI-01 — отсутствовали состояния ожидания/ошибки/устаревших
  данных.** Добавлены в Mini App, включая время последней синхронизации.
- [x] **P2 / UI-02 — статические макеты были набором отдельных экранов.**
  Сделаны связная навигация, адаптация под телефон, две темы, формы,
  доступные названия элементов, подтверждения удаления и управления.
- [x] **P2 / MONEY-01 — потеря копеек в уведомлении о капитале.**
  `trades.fmt_notification` округлял капитал и сумму на стратегии до целых.
  Возвращены два знака после запятой. Исходный `tools/selfcheck.py` падал
  на ожидании 142.63; после исправления проходит.
- [x] **P1 / MONEY-02 — NaN/Infinity/отрицательное значение Invested.**
  В API и обработчике `bot.py:cfg_base_set` добавлены конечность, диапазон
  и запрет правки демо/гостевых копий.
- [x] **P2 / SHARE-01 — повторная раздача дублировала один счёт гостю.**
  `accounts.share` проверяет login+server+owner; новые копии хранят `shared_by`.
  Для старых копий Mini App восстанавливает происхождение по приглашавшему
  и совпадению счёта. Это также ограничивает управление общим терминалом.
- [x] **P2 / TEST-01 — «офлайн» selfcheck мог обратиться к локальному MT5.**
  Выделен явный `TRADES_SOURCE=store`, тест принудительно использует
  временные accounts/state/trades и не затрагивает рабочие файлы.
- [x] **P2 / BUILD-01 — requirements не учитывали Linux и SOCKS.**
  MetaTrader5 ограничен Windows; добавлена зависимость `aiohttp-socks`,
  которую требует бот с SOCKS-прокси.

## Безопасность и доступ

- [x] **P0 / AUTH-02 — старый бот открывает данные известного MT5-логина
  без проверки нового пароля.** `bot.py:finish_add → connect → trades.use`
  в серверном режиме просто выбирает логин в БД. У другого пользователя
  `accounts.add` разрешает этот логин, а история общая по login.
  Исправлено: finish_add теперь запрещает присвоение известного логина
  другого владельца и доступ к осиротевшей истории. Для повторного
  подключения остаётся задача отдельного challenge проверки реквизитов.
  Приёмка: чужой логин + неверный пароль не дают ни баланс, ни историю.
- [ ] **P1 / AUTH-03 — непрозрачная видимость личных денег гостей.**
  `bot.py:_guest_money_lines`, `guest_view` рекурсивно показывают пригласившему
  собственные счета гостя и его гостей. Приветствие одновременно обещает
  «твои — никому другому». Новый подробный экран сохраняет поведение бота.
  Требуются явное согласие и модель «делюсь только отмеченными счетами».
- [x] **P1 / AUTH-04 — отзыв гостя удалял и его собственные счета.**
  Отзыв приглашения отделён от добровольного отключения: удаляются только
  копии, явно переданные этим владельцем. Личные счета и доступ гостя к
  собственному кабинету остаются. Совпадение номера MT5 само по себе не даёт
  права забрать счёт; проверено в API и обработчиках бота.
- [ ] **P2 / AUTH-10 — происхождение старых копий неоднозначно.**
  Ранее оно восстанавливалось по одному номеру MT5. Теперь новая копия
  помечается явно, а вывод о старой делается лишь при совпадении сервера,
  пароля и кабинета. Такие неопределённые записи защищены от автоматического
  удаления при отзыве; для них нужна индивидуальная сверка происхождения.
  Записи, уже помеченные прежним кодом только `shared_by` без `shared_origin`,
  тоже остаются неоднозначными: перед массовым отзывом нужна сверка владельца.
- [ ] **P1 / AUTH-05 — общий токен агентов даёт слишком широкие права.**
  `/agent/accounts` отдаёт пароли всех счетов; `/agent/env` раздаёт общий
  токен. Один скомпрометированный агент представляет любую машину.
  Нужны отдельные машинные ключи, отзыв и ограничение набора счетов.
- [ ] **P1 / AUTH-06 — токен вебхуков расположен в URL.**
  `webhook_urls`, query token и стандартные access logs могут сохранять
  секрет в журналах/истории. Маскировать query, отключить лишние логи,
  перейти на подписи или заголовок там, где это поддерживает отправитель.
- [ ] **P2 / AUTH-07 — investor-пароль только рекомендован.**
  Форма принимает любую строку; факт read-only доступа брокера не
  проверяется. Пароли лежат в accounts.json. Добавить проверку типа
  доступа, строгие права файлов и управляемое хранение секретов.
- [ ] **P2 / AUTH-08 — привязка кабинета не подтверждается.**
  Cabinet вводится пользователем; `holder_of`, `wallet_balance` используют
  записи этого кабинета глобально. Подтверждать принадлежность CU-номера,
  иначе угадывание номера может раскрывать чужое имя/расчёт кошелька.
- [x] **P2 / AUTH-09 — перезапуск общего терминала через старые callback.**
  Раньше `bot.py:restart_terminal` проверял только наличие копии счёта.
  Старый callback теперь, как и API, запрещает действие для
  гостевой копии и демо. Приёмка: приглашённый зритель не перезапускает MT5.

## Данные, расчёты и надёжность

- [ ] **P1 / DATA-02 — физический счёт идентифицируется непоследовательно.**
  `accounts.dedup` различает login+server, но state/deals/commands в `store.py`
  используют только login. Одинаковые номера у разных серверов смешают
  баланс/историю. Ввести account_id либо составной ключ во всех таблицах.
- [x] **P1 / DATA-03 — загрузка агента частично фиксировалась при ошибке.**
  `agent_sync` теперь валидирует весь пакет до записи. Состояние, сделки и
  подтверждение команды сохраняются одной SQLite-транзакцией; ошибка вставки
  откатывает все три изменения. Проверено тестом с принудительным отказом БД.
- [x] **P1 / DATA-04 — проверялась только дата сделки.**
  Проверяются объект пакета, номер счёта и тикета, ISO-время без зоны,
  конечность и диапазоны сумм, строки, флаги и дубли внутри пакета. При
  ошибке весь пакет отклоняется с 400, без потери истории и баланса.
- [ ] **P1 / MONEY-03 — выбор максимального капитала скрывает вывод.**
  `trades._stored_capital` возвращает `max(from_deals, from_agent)`.
  При устаревшем большем источнике после вывода капитала это завышает
  капитал и влияет на проценты. Нужны полнота/версия/время каждого
  источника и проверка сценария «вывод после последней синхронизации».
- [ ] **P1 / MONEY-04 — дедуп депозитов по сумме может терять реальные
  повторные пополнения.** `_just_sent` использует cabinet+amount без
  валюты и экономического ID. Два одинаковых депозита за HOOK_REPEAT
  считаются одним, в том числе для wallet_add. Нужен стабильный event ID.
- [ ] **P1 / DELIVERY-01 — seen фиксируется до гарантированной доставки.**
  Webhook `handle` и `poll_portal` записывают дедуп до отправки. После
  исчерпания ретраев или остановки процесса уведомление потеряется.
  Добавить долговечный outbox с отдельными received/sent/retry состояниями.
- [ ] **P2 / DELIVERY-02 — после простоя теряются события IB Portal.**
  `poll_portal` запрашивает последние 30 уведомлений без курсора обхода.
  Если за простой пришло больше 30, старые не будут обработаны.
  Добавить пагинацию до сохранённого checkpoint и сверку пропусков.
- [ ] **P2 / DELIVERY-03 — рассылка зависит от текущего HTTP-запроса.**
  Mini App имеет ключ повторной отправки, но после сбоя процесса нельзя
  надёжно возобновить только недоставленные сообщения. Нужна очередь с
  результатом по каждому адресату, обработкой 429 и экраном статуса.
- [ ] **P2 / HA-02 — устаревшая диагностика живости.**
  `machines_watchdog` опирается на machine_seen (heartbeat процесса), а
  не на успешный опрос. `/status` использует MAX(synced) по всем счетам,
  что скрывает один зависший счёт. Разделить process/lease/terminal/account
  health и показать причину ожидания/ошибки. Не лечить простым глушением алертов.
- [ ] **P2 / HA-03 — старый canary не доказывает непрерывную работу.**
  `agent_update_status` берёт первую отметку canary, не проверяет свежесть
  последней и последующие падения; возможны обновление по мёртвой канарейке
  и задержка восстановления после split-brain. Проверять свежий success,
  уникальную сессию и непрерывный период успешных синхронизаций.
- [ ] **P2 / HA-04 — синхронный MT5-вызов не прерывается при потере аренды.**
  Право проверяется до счёта, запись после истечения отклоняется. Если
  нативный вызов завис дольше TTL, новый владелец может уже работать.
  Нужны отдельный worker с жёстким дедлайном и завершением IPC-сессии;
  проверить отказ во время initialize/history, не только HTTP-загрузки.
- [ ] **P2 / HA-05 — зависимость агента от внешнего proxy окружения.**
  После возобновления задачи 16.09 около 19:15 лог показывает ProxyError
  на /agent/claim, /heartbeat и /update_report. Явно описать маршрут к
  собственному серверу и проверить доступность прямого канала, затем
  выбрать отдельную сессию requests/NO_PROXY. Не переключаться вслепую.

## Продукт и UI

- [ ] **P1 / UX-03 — состояние «проверяем пароль» не подтверждает пароль.**
  `finish_add` на сервере сообщает результат локального чтения БД, а
  `pending` не объясняет причину отказа брокера. Требуются per-account
  last_error, login_validated и состояния «неверный пароль / сервер /
  терминал недоступен», возможность исправить реквизиты без удаления.
- [x] **P2 / UX-04 — отключение отслеживания меняло сумму портфеля.**
  Пауза теперь останавливает опрос и уведомления, но счёт остаётся в списке
  с отметкой «На паузе» и в личной сводке по последним известным данным.
- [ ] **P2 / UX-05 — кошелёк приблизительный и без достоверной валюты.**
  `wallet_balance` не знает внешних выводов, хранит один float на cabinet.
  Недостоверный баланс и «обнуление учёта» удалены из Mini App. В боте
  старый расчёт остаётся; для возврата функции нужен настоящий Wallet API
  либо журнал ручных корректировок с валютой и датой сверки.
- [ ] **P2 / UX-06 — длинные имена ломают callback_data Telegram.**
  `menu`, `account_menu`, settings callbacks вставляют полное имя счёта.
  Telegram ограничивает callback_data 64 байтами, кириллица расходует их
  быстрее. Перейти на короткий account_id; проверить длинное имя с emoji.
- [ ] **P2 / UX-07 — HTML Telegram экранируется непоследовательно.**
  Например, `no_mt5`, `ranged`, `finish_add` подставляют имя/сервер в HTML.
  Символы `<`, `&` ломают сообщения. Использовать общий безопасный renderer.
- [ ] **P2 / UX-08 — ошибки редактирования сообщения скрываются.**
  `swap` глотает любой TelegramBadRequest как «текст не изменился».
  Невалидная разметка/длина клавиатуры остаётся без ответа. Обрабатывать
  только конкретный harmless error, остальные логировать и показывать fallback.
- [ ] **P2 / UX-09 — архивная детализация безвозвратно удаляется.**
  Ежемесячный rollup удаляет сделки, поэтому произвольный отчёт по дням
  прежнего месяца принципиально невозможен. Согласовать срок хранения,
  архивировать сырые сделки отдельно и явно показать доступную глубину.
- [ ] **P2 / UX-10 — `всем пользователям` означает только приглашённых.**
  `all_guests` не включает всех самостоятельных пользователей и основателя.
  Нужен единый реестр пользователей с явным состоянием подписки/доступа.
- [ ] **P2 / UX-11 — приемка в реальном Telegram WebView.**
  Проверены браузер и мобильные размеры; нужны Android/iOS Telegram,
  реальный запуск через меню, клавиатура, safe-area и долгоживущая сессия.
  Вручную не отправлялись рассылки и не удалялись реальные пользовательские данные.

- [x] **UI-12 — боковая карточка была общей рекламной фразой.** Заменена на
  компактную карточку SONIC с инструментом, доходностью, win rate,
  просадкой и ссылкой только на исходную публикацию стратегии.
