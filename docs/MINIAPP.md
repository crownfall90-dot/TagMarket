# TagMarkets Mini App

Рабочий интерфейс в стиле Pulse/Aurora. HTML/CSS/JavaScript без сборки;
backend — тот же aiohttp-процесс, который принимает данные агента.

## Запуск

Установить `requirements.txt` в серверное Python-окружение. Добавить только
новую настройку к существующему `.env`, не заменяя файл целиком:

```dotenv
MINI_APP_URL=https://crownfail.shop/tagmarkets/app/
TELEGRAM_BOT_USERNAME=tagmarketgold_bot
```

`python webhook_server.py` подключает API `/api/*` и frontend `/app/`.
Существующий nginx должен передавать `/tagmarkets/` на webhook-сервис со
снятием этого префикса. Для рассылки с вложением в этом location требуется
`client_max_body_size 22m` (фото до 10 МБ, MP4 до 20 МБ). Сервис по умолчанию
слушает только localhost.
При запуске `bot.py` устанавливается стандартная кнопка меню Telegram
«Открыть приложение». Обычная ссылка в браузере не заменяет запуск из бота:
для личных данных требуется подписанный Telegram initData.

## Возможности

| Сценарий | Реализация |
| --- | --- |
| Общая картина | TagMarket / Все активы, глобальное отображение USD/BYN/RUB по кешируемому FX MYFIN · НБРБ; демо и общие счета исключены |
| Кабинеты | Группировка счетов и отчёт кабинета за выбранный стандартный период |
| Счёт | Капитал, чистый результат, ROI, график, месячная история |
| Проекты | Личные и бонусные балансы, срок бонуса, single/multi, независимая капитализация и отдельный прогноз |
| Периоды | Сегодня, вчера, неделя, предыдущая неделя, месяц, предыдущий месяц, вся история, даты |
| Операции | Сделки/движения, процент к капиталу на дату сделки, страницы по 50, архивные месячные суммы |
| Управление | Добавить, переименовать, удалить личную запись; Invested |
| Уведомления | Общий и отдельные переключатели, единые с ботом; личная лента новых сделок, событий кабинета и сообщений с отметкой прочтения |
| Демонстрация | Отдельный наблюдаемый счёт, показ/скрытие, уведомления |
| Гости | Выданные счета с актуальным балансом на общей главной, приглашения с выбором счетов, список и отзыв только переданных копий; инструкция своего счёта открывается по запросу |
| Ссылки | Одноразовые ссылки `t.me/...?...`, копирование, отзыв |
| Терминал | Постановка команды перезапуска для собственного счёта |
| Основатель | Статус машин, служебные уведомления, доход сети, рассылка с форматированием, JPG/PNG до 10 МБ и MP4 до 20 МБ |
| Отключение | Удаление своих данных/доступа с подтверждением, кроме основателя |
| Telegram | Проверка подписи initData, BackButton, тема, safe-area |

Новый брокерский трейдинг, реальные переводы/вывод денег не реализованы:
таких поддерживаемых действий в действующем боте/API нет. Не создаются
кнопки, которые обещают несуществующую операцию.

## Общие данные и безопасность

- Счета и настройки — `accounts.py` и существующий accounts.json.
- Лента уведомлений хранится в `partner.py` по Telegram user_id; события
  дедуплицируются, чужие записи нельзя прочитать или отметить прочитанными.
- Капитал, прибыль, месячные итоги — общие `trades.py`/`store.py`.
- Для общей сводки RUB и BYN переводятся в USD по текущим котировкам из таблицы
  официальных курсов НБРБ на MYFIN. Счета и их история остаются в исходной валюте.
  Курсы отдаёт единый сервис `fx.py`: MYFIN (таймаут 4 с) → официальный API НБРБ
  (`api.nbrb.by/exrates/rates`) → последний сохранённый курс (`kv` `fx:last_good`,
  в ответе `fx.provider="cache"`, `fx.stale=true`, UI: «Используется последний
  доступный курс от HH:MM»). Курсы разных источников не смешиваются; ответ
  проверяется (USD и RUB есть, конечны, > 0, дата разумна). На каждом обновлении
  снова пробуется MYFIN. Если не было ни одного курса, суммы остаются в исходной
  валюте с предупреждением «Курс валют временно недоступен».
- Гости, ссылки, настройки — существующая `partner` SQLite KV.
- Сервер всегда читает БД, даже если установлен Python-пакет MetaTrader5.
- Мутации accounts.json защищены межпроцессной блокировкой.
- API принимает только `X-Telegram-Init-Data`; user_id из тела игнорируется.
- Проверяются HMAC, auth_date (24 часа), отозванный доступ и владелец ресурса.
- Пароли не попадают в JSON API, JavaScript, localStorage или preview.
- Передача уже существующего счёта — приглашением. Введённый наугад номер
  не даёт доступ к сохранённой истории. Для переподключения осиротевшей
  истории пока требуется администратор (см. todo.md).
- Обновление интерфейса: раз в минуту (интервал задаёт `refresh_seconds` в
  `/api/bootstrap`, не чаще 30 секунд), пауза в скрытой вкладке/открытом диалоге.
- API возвращает no-store; статические файлы требуют проверки свежести.
- Формат Telegram HTML преобразуется в обычный текст на сервере; клиент
  экранирует пользовательские значения.

Алгоритм авторизации сверён с [официальной документацией Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).

## Проекты

Раздел «Проекты» — отдельная вкладка между «Счета» и «Гости». Проекты не
участвуют в капитале, прибыли, ROI, комиссиях и графиках MT5. В интерфейсе
TagMarket показывается отдельным системным элементом портфеля. Режим «Все
активы» объединяет только личный капитал торговых счетов и Projects.

В той же серверной SQLite (`STATE_DB`, обычно `data/state.db`) создаются
таблицы `projects` и `project_accounts`. В проекте хранятся UUID, Telegram
владелец, название, валюта, общая ставка, период (`day/week/month`), `multi`,
режим капитализации и дата начала. Аккаунт содержит свой UUID, `project_id`,
необязательное название, личный баланс в целых копейках и порядок; собственные
ставка и капитализация могут переопределять настройки проекта. У аккаунта
также хранятся бонус, время активации, `bonus_expires_at` и независимая
капитализация бонуса. Есть индекс владельца и FK с каскадным удалением. Схема
создаётся и мигрируется при запуске Mini App.
В `accounts.json` эти записи не записываются.

Обычный проект содержит один внутренний аккаунт. Включение «Несколько
аккаунтов» сохраняет его ID и сумму. Без названия UI показывает «Аккаунт N».
Проект можно редактировать, а в multi добавлять/изменять/удалять аккаунты.
Удаление требует подтверждения. Последний аккаунт удаляется вместе с проектом;
для переключения multi → single сначала оставьте один аккаунт.
При попытке закрыть изменённую форму, перейти дальше или открыть поверх неё
другой диалог Mini App просит подтвердить выход без сохранения.

`total` — внесённые личные средства; `current_total` — серверный расчёт личной
суммы с завершившимися периодами капитализации. `bonus_total` — активные бонусы
с учётом их отдельной капитализации; `working_total` равен текущим личным
средствам и активным бонусам. `expected_income` считается от рабочего капитала
по ставке аккаунта (или проекта, если собственная ставка не задана). Бонус
после срока остаётся в записи для редактирования, но исключается из рабочего
капитала и будущего прогноза. На карточке показываются личные средства,
активный/истёкший бонус, рабочий капитал и ставка; если капитализация изменила
личный остаток, отдельно указаны вложенная и расчётная суммы.

Для дневной ставки проекта можно выбрать начисление каждый календарный день
или только по будням. Режим будней учитывает понедельник–пятницу при расчёте
текущего баланса с капитализацией и прогноза; недельная и месячная ставки
остаются привязаны к своим периодам. В карточке TagMarket показывается чистый
результат последнего дня с закрытыми сделками, общего для личных счетов;
выходные и дни без сделок пропускаются. Демо- и выданные счета в сумму не входят.

`GET /api/projects/forecast?until=YYYY-MM-DD` возвращает текущую сумму и
контрольные точки на день, неделю, календарный месяц и указанную дату. Для
каждой точки доступна разбивка по внутренним аккаунтам и расчётный прирост.
Личный баланс и бонус рассчитываются независимо, каждый со своим режимом
капитализации. В режиме «Только мои средства» бонус полностью исключён. Если
бонус истекает до контрольной даты, после срока он больше не участвует в базе
и доходности.

Для TagMarket `GET /api/tagmarket/forecast?until=YYYY-MM-DD` строит статистический
прогноз по средней исторической доходности собственных счетов (без демо и
выданных). Для каждого завершённого торгового дня (в нём закрывались сделки;
сегодняшний день не считается) доходность равна чистому результату дня к капиталу
на начало дня (`trades.capital_at`), по счетам суммарно в USD. Берутся последние
30 таких дней, не меньше 5; нулевые дни не добавляются. Прогноз идёт с
накоплением: `капитал × (1 + средняя дневная доходность) ^ торговые дни`, где
торговые дни — будни между сегодня (не включая) и датой точки. Отрицательное
среднее даёт снижение, нулевое — горизонталь. Сервер отдаёт множители по точкам;
интерфейс применяет их к текущему капиталу и переводит через единый снимок курса
(будущий курс не прогнозируется). Если истории меньше порога, показывается
«Недостаточно истории для статистического прогноза TagMarket» и текущий капитал.
Это статистическая оценка, а не обещание результата; фактический баланс не меняется.

Карточки и прогноз используют вычисленные сервером суммы, второй расчёт этих
значений в интерфейсе не выполняется. На телефоне контрольные точки показаны
карточками. Если курс для глобальной валюты недоступен, сумма проекта остаётся
видимой в исходной валюте, а сводка отмечается как частично рассчитанная.
Валюты проекта не меняются; FX используется только для отображения и берётся
из единого сервиса курсов `fx.py` (MYFIN · НБРБ с резервом, см. выше); Обзор, Проекты и Прогноз используют один снимок `fx` из `/api/bootstrap`. Предпочтение USD/BYN/RUB
хранится в `kv` по Telegram user ID.

API: `GET/POST /api/projects`, `GET/PATCH/DELETE /api/projects/{project_id}`,
`POST /api/projects/{project_id}/accounts`,
`PATCH/DELETE /api/projects/{project_id}/accounts/{account_id}`.
Пользовательские настройки отображения: `GET/PUT /api/preferences/display-currency`.
Редактирование проекта может атомарно сохранить весь список аккаунтов,
сохраняя их ID. Авторизация — существующий подписанный Telegram initData;
владелец из тела запроса не используется. Чужой проект/аккаунт возвращает 404.
Каждая мутация проходит транзакцию и серверную проверку данных.

Ограничения первой версии: название до 96 символов, USD/RUB/BYN, положительные
суммы с точностью до копеек, сумма проекта до 1 трлн, процент 0–1000 (до четырёх
знаков после запятой), до 100 аккаунтов. Валюта с вложениями фиксирована;
для другой валюты создаётся другой проект. Данные сохраняются на сервере и
доступны тому же Telegram пользователю на другом устройстве.

Предпросмотр содержит «Недвижимость» и multi-проект «Private Invest» с тремя
аккаунтами. Как и остальные изменения в preview, сохранение отключено.

После полного вывода капитала подтверждённый нулевой баланс имеет приоритет
над ручным Invested. При синхронизации нулевого баланса с выводом капитала
после даты привязки ручные `base/base_at` сбрасываются. При частичном выводе
действующий расчёт показывает остаток капитала; значения не уходят в минус.

## Предпросмотр дизайна

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory web
```

Открыть `http://127.0.0.1:8765/?preview=1`. Используются только вымышленные
записи из `web/preview.json`; изменения отключены. Этот режим не отключает
серверную авторизацию и не может получить реальные данные.
Образец сделок в предпросмотре фиксирован; реальные фильтры периода работают
с серверным API после открытия приложения через Telegram.
Демо-режим не отправляет рассылки. Кнопка ярлыка в обычном браузере показывает
путь через Telegram; нативное добавление доступно только при поддержке клиента.

## Проверки

```powershell
python tests/selfcheck.py
python tests/test_miniapp.py
node --check web/app.js
python tests/ui_smoke.py
```

Тесты создают временные БД и accounts.json. Рассылки реальным пользователям,
удаления реальных данных и брокерские операции не выполняются.
Проверка интерфейса использует локальный Chromium Playwright с вымышленными
данными и проходит ширины 390 и 1280 px, переходы, периоды и выбор кабинета.
При каждом обновлении дополнительно проверяются изменённые сценарии в
мини-приложении на мобильной ширине. Скрипт развёртывания повторяет оба набора
тестов и проверку JavaScript, затем сверяет опубликованные HTML, JS, CSS и
логотип с установленными файлами. Если версия по публичному адресу не совпала
или службы не поднялись, развёртывание откатывается. Реальные операции MT5 и
доставку Telegram это не подменяет: их состояние проверяется отдельно.

## Координация машин

`/agent/claim` выдаёт право опроса одному host+session на 180 секунд.
Успешная `/agent/sync` продлевает срок; heartbeat не продлевает его.
Основная машина (`AGENT_ROLE=primary`) забирает право у резервной сразу, даже
если аренда резерва ещё жива: резерв работает, только пока основная не
отвечает. Остальные ждут текущего владельца. После отказа владелец отдаёт
другой машине окно для перехвата; истёкшие загрузки отвергаются.
Список счетов выдаётся только владельцу через X-Agent-Host/Session.

Устанавливать сначала сервер с endpoint claim, затем агентов.
Основная машина переходит на новый коммит, только когда другая машина
проработала на нём `CANARY_DELAY` (30 минут): в зачёт идёт время между её
первым и последним отчётом, и только пока она остаётся на этом коммите —
упавшая или откатившаяся канарейка обновление не разрешает.
Подробные ограничения нативных MT5-вызовов указаны в todo.md.

## Установка и откат

Сервер выкладывается сам после каждого зелёного CI на `main`
(`.github/workflows/deploy.yml`, нужны секреты `VPS_SSH_KEY` и
`VPS_KNOWN_HOSTS`), вручную — `tools/deploy-miniapp.bat` с ПК или
Actions → Deploy → Run workflow. Оба пути зовут `tools/deploy_cli.py`: он
собирает архив строго из `FILES` выкладываемого коммита (из git, без `.env`,
`data/` и локальных правок), отправляет его на VPS и запускает там
`deploy_miniapp.py` этой же ревизии. Выложенный коммит записывается в
`/opt/tagmarkets/.deployed_commit`; если с тех пор файлы сервера не
менялись, выкладка пропускается и сервисы не перезапускаются (откат метку
снимает). Снимков выкладок хранится 15 последних, распакованных архивов — 10.

`tools/deploy_miniapp.py` предназначен только для существующего Linux VPS
`/opt/tagmarkets`. Принимает подготовленный архив исходников, проверяет
синтаксис и тесты в отдельной папке, сохраняет старые файлы и `.env`,
останавливает оба сервиса на время замены, добавляет MINI_APP_URL и
проверяет локальные health/API endpoints. При ошибке возвращает прежний код
и настройки. Пользовательские базы не заменяются архивом исходников.

Перед каждым развёртыванием сохраняется снимок кода, настроек и баз на VPS.
Для просмотра последних десяти **совместимых** версий и отката кода запустите
`tools/rollback-miniapp.bat` в локальной папке проекта. Нужен настроенный SSH-адрес
`tagvps`. Выберите номер версии и подтвердите словом `ROLLBACK`. Сервер перед
откатом сохранит текущий код, остановит оба сервиса, восстановит выбранную
версию и проверит `/health`, интерфейс и защиту API. Если проверка не пройдёт,
он автоматически вернёт предыдущий код. Счета, торговая история, ключ
шифрования и текущие настройки не перезаписываются. Время в списке — UTC.
Ранние версии без поддержки зашифрованных паролей MT5 не предлагаются:
они несовместимы с текущими данными. Снимки исходников и баз находятся в
`/opt/tagmarkets/backup/`; локальный BAT управляет ими через SSH и не скачивает
персональные данные.

Архив нельзя собирать из `.env`, `data/`, `logs/` или локальной памяти.
Автообновление агентов распространяется отдельно через Git. Фактический
статус текущей установки записан в todo.md.

# Защита данных MT5

Пароли MT5 хранятся в `accounts.json` в зашифрованном виде. Ключ находится рядом
с файлом счетов в `accounts.json.key` (или по пути `ACCOUNTS_KEY_FILE`) и создаётся
с правами `0600`. При первом обновлении старые записи мигрируют автоматически.
Для восстановления счетов нужны и файл счетов, и соответствующий ключ;
сохраните ключ в защищённой резервной копии отдельно от исходного кода.
