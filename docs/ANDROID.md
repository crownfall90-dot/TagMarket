# Platformer для Android (Google Play)

Приложение лежит в `android/`. Это нативная оболочка на Kotlin вокруг того же
интерфейса, что и Mini App. Своё у неё вот что:

- **Вход по коду из бота.** На экране входа кнопка «Запросить код» открывает бота
  (`?start=login`), и он сразу присылает код из 8 символов на 10 минут с кнопкой
  «Скопировать код». Вернулись в приложение — код подставляется из буфера и вход идёт сам.
  Код всё равно вводится в приложении: войти может только тот, кто видит чат с ботом.
  Команда `/app` в боте делает то же самое. Приложение обменивает код на токен устройства
  через `POST /api/device/pair`.
  Токен шифруется ключом из Android Keystore. На сервере хранится только его SHA-256.
  Отвязать телефон: «Выйти» в настройках (`POST /api/device/logout`), `/app_logout` в боте,
  `DELETE /api/devices/{id}` или `/stop`.
- **Шаги из Health Connect.** Приложение читает только `READ_STEPS`, плюс чтение в фоне,
  если телефон это поддерживает. Это суммы по дням за неделю. Они уходят в
  `/api/activity/sync` раз в 15 минут через WorkManager и при каждом открытии приложения.
- **Обновляется само.** Два варианта сборки:
  - `direct` — APK для установки напрямую. При каждом входе приложение читает `latest.json`
    из релиза `android-latest` на GitHub. Если версия новее, приложение закрывается окном
    обновления: номер версии, «Что нового» (из `android/whatsnew.txt`) и «Обновить до …».
    Обновление обязательное, кнопки «Позже» нет. Без интернета окно прямо говорит, что
    проверить обновление нельзя, и повторяет проверку, как только появится сеть. По кнопке
    приложение скачивает APK и сверяет
    SHA-256, имя пакета, номер версии и подпись с установленным. Потом ставит его через
    PackageInstaller: на Android 12+ без вопросов, на старых — одно «Установить». В первый
    раз Android попросит разрешить Platformer устанавливать приложения.
  - `play` — для Google Play: обновление через Play (In-App Updates, сразу при входе).
    Права ставить APK у этой сборки нет: Google Play запрещает приложениям обновляться в обход Play.

  Веб-интерфейс внутри обоих вариантов обновляется с сервера после каждого деплоя. Новый APK
  нужен только при изменениях самой оболочки.
- **Уведомления на телефон.** Те же события, что в колокольчике приложения: пополнения,
  выводы, профит, напоминания. WorkManager раз в 15 минут берёт новые события из
  `GET /api/notifications` и показывает их системными уведомлениями (канал «События»).
  На Android 13+ разрешение спрашивается один раз. Пока приложение открыто, системные
  уведомления не дублируют страницу.
- **Мгновенные уведомления (Firebase).** Если в сборке есть настройки Firebase, приложение после
  входа отдаёт серверу свой FCM-токен (`POST /api/device/push`). Сервер (`push.py`) раз в 3 секунды
  отправляет новые события на телефоны владельца. Без настроек остаётся проверка раз в 15 минут.

  Включить:
  1. В [Firebase Console](https://console.firebase.google.com) создайте проект и добавьте
     Android-приложение с пакетом `app.platformer.android`. Скачайте `google-services.json`.
  2. GitHub → Settings → Secrets and variables → Actions:
     - вкладка **Variables** → `PLATFORMER_FIREBASE`: содержимое `google-services.json` целиком;
     - вкладка **Secrets** → `FCM_SERVICE_ACCOUNT`: ключ сервера. В Firebase: Project settings →
       Service accounts → Generate new private key, вставьте содержимое JSON целиком.
  3. Перезапустите Android и Deploy (Actions → Run workflow). Сборка подхватит настройки,
     деплой положит ключ на сервер (`data/fcm-service-account.json`, доступ только владельцу).
- **Сон и пульс.** Из Health Connect: длительность сна за ночь (с 18:00 накануне до 18:00),
  пульс покоя, средний и максимальный за день. Нужны разрешения `READ_SLEEP`,
  `READ_HEART_RATE`, `READ_RESTING_HEART_RATE`. Тех, кто раньше разрешил только шаги,
  приложение спросит один раз.
- **Шаги со счётчика телефона.** Health Connect не всегда видит встроенный трекер телефона
  (например, у Realme). Поэтому есть второй источник — Recording API сервисов Google Play
  (`StepRecorder`). Сервисы Google Play сами считают шаги в фоне по датчику телефона и
  хранят их до 10 дней. Нужно разрешение «Физическая активность» (`ACTIVITY_RECOGNITION`).
  За каждый день на сервер уходит большее из двух значений. Счёт начинается с подписки,
  поэтому первый день может быть неполным.
- **Без интернета.** Показывается своя страница с кнопкой «Повторить».
- **Ссылки.** Ссылки на Telegram и сайты открываются во внешних приложениях.
  Мост `window.PlatformerAndroid` доступен только страницам Platformer.
- **Внешний вид.** Две темы в стиле Aura — тёмная фиолетовая (по умолчанию) и светлая, выбор в «Настройках →
  Оформление». Нижние вкладки — плавающий док, окна — листы снизу, отклик вибрацией,
  «Назад» сначала закрывает окна. Цвет полос под статус-баром и жестами следует теме
  страницы. Выбранную тему приложение запоминает (`AppTheme`): экран входа, окно
  обновления и страница «нет соединения» открываются в ней же (цвета — из `values`
  для светлой и `values-night` для тёмной), на Android 12+ и системная заставка.
- **Обновления.** При входе в приложение (запуск или возвращение после минуты в фоне)
  новая версия обязательна. Пока приложение открыто, новая версия ищется раз в минуту
  и всплывает сразу: что нового, «Обновить» и «Обновить позже» — «позже» действует
  до выхода из приложения. Вышла новая версия, а приложение закрыто — фоновая проверка
  (раз в 15 минут, вместе с событиями) присылает уведомление «Мы обновились · Platformer
  0.3.N — зайдите, чтобы посмотреть, что изменилось» с кратким «что нового»; о каждой
  версии — один раз. С Firebase оно приходит сразу: сервер раз в минуту смотрит
  latest.json релиза и рассылает новую версию через FCM. Нужно разрешение на уведомления.
- **Любые экраны.** Узкие телефоны от 320 px, планшеты и раскладушки (широкий экран —
  с боковым меню), вырезы камеры, поворот без перезагрузки страницы, крупный системный
  шрифт в пределах 85–120 %.
- **Защита.** Только HTTPS (cleartext запрещён), смешанный контент запрещён, нет доступа
  к файлам, Safe Browsing, отладка WebView только в debug-сборке, резервное копирование
  выключено. Упавший процесс страницы пересоздаёт экран, а не роняет приложение.

## Сборка

```bash
cd android
printf "sdk.dir=/путь/к/android-sdk\nplatformer.url=https://ваш-домен/app/\n" > local.properties
./gradlew :app:assembleDirectRelease   # APK для установки на телефон (обновляется сам)
./gradlew :app:bundlePlayRelease       # AAB для Google Play
```

`platformer.url` — это тот же адрес, что `MINI_APP_URL` на сервере. Без него приложение
соберётся, но экран входа скажет, что адрес сервера не задан.

В CI сборку запускает `.github/workflows/android.yml`: на каждое изменение в `android/`
и по кнопке «Run workflow». APK и AAB лежат в артефактах запуска.

Что нужно задать в GitHub (Settings → Secrets and variables → Actions):

| Где | Имя | Что |
| --- | --- | --- |
| Variables | `PLATFORMER_URL` | адрес Mini App, `https://…/app/` |
| Variables | `PLATFORMER_BOT` | имя бота без @ (по умолчанию `tagmarketgold_bot`) |
| Secrets | `PLATFORMER_KEYSTORE_B64` | ключ загрузки (`.jks`) в base64 |
| Secrets | `PLATFORMER_KEYSTORE_PASSWORD`, `PLATFORMER_KEY_ALIAS`, `PLATFORMER_KEY_PASSWORD` | пароли ключа |

Без секретов AAB собирается неподписанным: для проверки он годится, для загрузки в
Google Play — нет. Ключ создаётся один раз и в репозиторий не кладётся:

```bash
keytool -genkeypair -v -keystore upload.jks -alias upload -keyalg RSA -keysize 4096 -validity 10000
base64 -w0 upload.jks     # → секрет PLATFORMER_KEYSTORE_B64
```

`versionCode` в CI — это 100 + номер запуска сборки, поэтому каждая новая сборка выше
предыдущей. У собранной вручную `versionCode` равен 100.

## Публикация в Google Play — что сделать владельцу

1. **Аккаунт разработчика** в Google Play Console: разовый взнос $25 и подтверждение
   личности.
2. **Пакет `app.platformer.android`.** После первой загрузки его нельзя сменить. Если
   нужен другой, поменяйте `applicationId` в `android/app/build.gradle.kts` до первой загрузки.
3. **Play App Signing.** Загрузите подписанный AAB. Google хранит ключ подписи
   приложения, а у вас остаётся только ключ загрузки.
4. **Политика конфиденциальности:** `https://ваш-домен/app/privacy.html` (лежит в `web/privacy.html`).
5. **Data safety.** Собираются:
   - идентификатор пользователя (Telegram ID);
   - финансовая информация, которую человек вводит сам;
   - фитнес-данные (шаги, сон и пульс из Health Connect, шаги со счётчика телефона — разрешение «Физическая активность»).

   Данные передаются только по HTTPS, третьим лицам не отдаются, удаляются по
   запросу (`/stop`).
6. **Health Connect.** Заполните декларацию разрешений: `READ_STEPS` нужен для
   раздела «Шаги». Фоновое чтение нужно, чтобы шаги обновлялись без открытия
   приложения. Окно с объяснением уже есть: `HealthRationaleActivity`.
7. **Доступ для проверки.** Вход по приглашению, поэтому Google нужен способ войти.
   Дайте в «App access» инструкцию и тестовый код или выделенный тестовый аккаунт.
   Код живёт 10 минут, поэтому для ревьюера удобнее заранее привязанный тестовый
   Telegram-аккаунт: ревьюер сам нажимает «Запросить код».
8. **Закрытое тестирование.** Новые личные аккаунты разработчика должны провести
   закрытый тест: не меньше 12 тестировщиков в течение 14 дней. Только после этого
   откроется доступ к публикации в «Рабочую версию».
9. **Возрастной рейтинг, целевая аудитория (18+), категория.** Категория — «Финансы»
   или «Продуктивность».

## Риски на проверке

- **«Минимальная функциональность».** Google отклоняет приложения, которые просто
  показывают сайт. Своё здесь есть: вход по коду, шаги из Health Connect в фоне,
  страница без сети, нативный экран входа. Но основной интерфейс — веб. Если
  проверка всё же отклонит, следующий шаг — нативные экраны главных разделов.
- **Вход только по приглашению.** Ревьюеру обязательно нужен рабочий способ войти, см. пункт 7.
- **SMS банков.** В приложение для Google Play это намеренно не добавлено: доступ к SMS
  Google разрешает почти только приложениям SMS по умолчанию.
