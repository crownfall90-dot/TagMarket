# Как прогнать audit.py на боевом сервере

`tools/audit.py` сверяет расчёты на реальных данных — но ему нужны файлы,
которых нет в этой копии репозитория (`data/accounts.json`, `data/trades.db`,
`data/state.db`, `.env`). Эта машина хранит только исходники, а боевые данные
живут на сервере, где крутится `bot.py`/`webhook_server.py`.

## Запуск

На сервере, в корне проекта (там, где лежит папка `data/`):

```bash
python tools/audit.py
```

Каждая строка — либо `✔` (сошлось), либо `✘` (расхождение) с деталями.
В конце — либо `ВСЁ СХОДИТСЯ`, либо список найденных проблем.

## Что именно проверить в контексте текущих жалоб

1. **Профит "неправильный много где"** — раздел `═══ РАСЧЁТЫ ПО СЧЕТАМ ═══`:
   - `сумма месяцев = заработано` — если разошлось, конкретный счёт и цифры
     сразу видны в выводе.
   - `доходность = произведение месяцев` — то же для процентов.
   - `Invested против истории` — сверяет введённый вручную `base` (Invested
     из портала) с тем, что бот насчитал сам по истории терминала. Большое
     расхождение здесь ("← стоит сверить с порталом") — прямой кандидат на
     причину неверного профита у конкретного счёта.

2. **Капитал не растёт после депозита** — после моего фикса в
   [trades.py](trades.py) (`since_ticket` больше не режет историю до 3 дней)
   проблема должна уйти сама при следующей синхронизации агента. Чтобы
   убедиться:
   - Раздел `═══ СВЯЗЬ С АГЕНТОМ ═══` — колонка "сек назад" не должна расти
     (агент должен быть на связи, иначе новые данные вообще не дойдут).
   - Пункт 4 `капитал восстановим` — если `1-е число` больше, чем `сейчас`,
     это тоже сигнал неладного с движениями капитала.
   - Если после фикса и синка агента расхождение по конкретному счёту
     останется — пришлите мне точный `comment` балансовой сделки перевода
     из истории MT5 по этому счёту (Терминал → История → правый клик →
     свойства сделки, или `mt5.history_deals_get(...)` в Python). Возможно,
     формулировка не входит в список `TRANSFER_WORDS` в
     [trades.py](trades.py):
     ```python
     TRANSFER_WORDS = ("deposit", "withdraw", "upgrade", "transfer", "credit", "adjust")
     ```

3. **Holder не пишется** — раздел `═══ НАСТРОЙКИ И ССЫЛКИ ═══`, пункт
   "стратегия повторяется": если у одного человека часть счетов имеет
   `holder`, а часть — нет (из-за старого бага, который я поправил), эта
   проверка их не свяжет. Стоит вручную посмотреть `data/accounts.json` на
   пустые `"holder": ""` у счетов с непустым `"cabinet"` — это счета, которым
   имя владельца нужно дозаполнить руками через `/cfg` → счёт → (или
   пересоздать через `/start` → добавить счёт, теперь бот спросит имя сам,
   если кабинет новый).

## Если что-то не сошлось

Пришлите вывод `audit.py` целиком (или хотя бы строки с `✘`) — по ним я
смогу указать точную причину и поправить конкретное место в коде, а не гадать.
