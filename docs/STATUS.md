# Статус проекта, архитектура безопасности и руководство

## 1. Архитектура надёжного фуллстека и безопасность

### 1.1. Клиентская безопасность (Mini App & Web)
* **Защита от Clickjacking:** Заголовки CSP `frame-ancestors 'self' https://web.telegram.org` гарантируют, что веб-приложение может встраиваться только во фреймы официального Telegram Web, исключая возможность перехвата кликов сторонними сайтами.
* **Content Security Policy (CSP):**
  - `default-src 'self'` — запрет загрузки ресурсов с непроверенных доменов.
  - `script-src 'self' https://telegram.org` — выполнение скриптов разрешено только из нашего бандла и официальной библиотеки Telegram WebApp SDK.
  - `connect-src 'self'` — сетевые запросы приложения ограничены собственным API.
  - `base-uri 'none'`, `object-src 'none'` — исключение внедрения Flash/Java апплетов и подмены базы путей.
* **Защитные HTTP-заголовки:**
  - `X-Content-Type-Options: nosniff` — предотвращение MIME-sniffing атак.
  - `Strict-Transport-Security: max-age=31536000; includeSubDomains` (HSTS) — принудительный HTTPS на всех уровнях.
  - `Referrer-Policy: no-referrer` — конфиденциальность путей и отсутствие утечки служебных заголовков.
  - `Cross-Origin-Opener-Policy: same-origin` и `Cross-Origin-Resource-Policy: same-origin` — изоляция контекста браузера.
  - `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()` — блокировка неиспользуемых разрешений оборудования.
* **XSS-санитайзинг:** Все динамические строки экранируются функцией `esc()` перед вставкой в DOM (`& -> &amp;`, `< -> &lt;`, `> -> &gt;`, `" -> &quot;`).

### 1.2. Аутентификация и авторизация (Auth & Access Control)
* **Валидация Telegram WebApp:** Подпись запросов `X-Telegram-Init-Data` проверяется через криптографический HMAC-SHA256 с использованием секретного ключа бота (`HMAC_SHA256(bot_token, "WebAppData")`). Подделать `initData` невозможно.
* **Токены устройств Android:**
  - Токены устройств генерируются криптографически стойким генератором (`secrets.token_urlsafe(32)`).
  - На сервере токен устройства **никогда не хранится в открытом виде** — хранится только его криптографический хеш SHA-256 (`token_hash`).
  - На Android-устройстве токен шифруется аппаратно с помощью **Android Keystore** (AES-GCM / RSA).
* **Rate-limiting (Защита от перебора и DoS):**
  - Лимит 120 запросов в минуту на пользователя / устройство.
  - При превышении отдаётся HTTP 429 (`Слишком много запросов. Подождите минуту`) без нагрузки на базу данных.

### 1.3. Серверная безопасность и БД (Backend & SQLite)
* **SQL Injection Prevention:** 100% запросов к базе данных параметризованы через SQLite placeholders (`?`). Строковая конкатенация пользовательских данных в SQL-запросах полностью исключена.
* **Транзакционная целостность:** Операции записи выполняются в блоках `with db:` (контекстный менеджер транзакций SQLite). Включён режим WAL (`Write-Ahead Logging`) для одновременного неблокирующего чтения и надёжной записи.
* **Изоляция счетов и прав:** Все эндпоинты проверяют принадлежность счёта / проекта авторизованному `uid` (`owned(uid, login)`). Доступ гостей строго ограничен правами, выданными владельцем.
* **Взаимодействие с агентом MT5:**
  - Запросы агента (`/agent/sync`, `/agent/claim`) защищены секретным ключом `X-Token` / `AGENT_SECRET`.
  - Валидация типов параметров предотвращает подмену логинов MT5 (только положительные 64-битные целые числа).
  - Секретные ключи Telegram-бота и портала брокера не передаются агенту и изолированы на сервере.

## 2. Мобильное приложение (Android APK) и автообновление

### 2.1. Механизм самообновления (Direct Release)
* **Проверка версий:** Приложение (`Updater.kt`) при каждом входе или раз в минуту в фоне обращается к `latest.json` релиза `android-latest` на GitHub.
* **Контроль целостности и подписи:**
  - Скачанный APK проверяется по контрольной сумме SHA-256.
  - Проверяется имя пакета (`app.platformer.android`) и номер версии `versionCode`.
  - **Верификация подписи сертификата:** проверяется, что публичный ключ подписи скачанного APK совпадает с сертификатом уже установленного приложения. Чужой APK никогда не будет запущен установщиком.
* **Автоматическая установка:** На Android 12+ (API 31+) установка запускается через `PackageInstaller` с параметром `USER_ACTION_NOT_REQUIRED` — обновление ставится бесшовно.
* **Постоянный ключ подписи direct-сборок:** В репозиторий добавлен постоянный сертификат `android/direct-release.p12`. Теперь каждая сборка GitHub Actions для варианта `directRelease` подписывается единым ключом, даже если в секретах GitHub ещё не настроен ключ для Google Play Console.

## 5. Что требуется от владельца (Action Items)

### А. Ничего не требуется для базовой работы:
* Бот `@tagmarketgold_bot`, Mini App и сервер на VPS уже обновлены, синхронизированы и работают штатно.
* Готовый APK для телефона доступен по постоянной ссылке в GitHub Releases:
  `https://github.com/crownfall90-dot/TagMarket/releases/download/android-latest/Platformer.apk`
* Приложение будет самостоятельно проверять обновления с GitHub и обновляться.

### Б. Если вы хотите включить мгновенные Push-уведомления (Firebase):
1. Зайдите в [Firebase Console](https://console.firebase.google.com/) и создайте проект.
2. Добавьте Android-приложение с пакетом `app.platformer.android` и скачайте `google-services.json`.
3. В Firebase: *Project Settings → Service Accounts → Generate new private key* (скачается JSON-файл).
4. В вашем GitHub репозитории (*Settings → Secrets and variables → Actions*):
   - Во вкладке **Variables** добавьте переменную `PLATFORMER_FIREBASE` (содержимое файла `google-services.json`).
   - Во вкладке **Secrets** добавьте секрет `FCM_SERVICE_ACCOUNT` (содержимое JSON-ключа сервисного аккаунта).

### В. Если вы захотите выпустить приложение в Google Play:
1. Создать аккаунт в Google Play Console.
2. Сгенерировать ключ подписи загрузки (`upload.jks`):
   ```bash
   keytool -genkeypair -v -keystore upload.jks -alias upload -keyalg RSA -keysize 4096 -validity 10000
   ```
3. Закодировать его в base64 и добавить в GitHub Secrets:
   - `PLATFORMER_KEYSTORE_B64`
   - `PLATFORMER_KEYSTORE_PASSWORD`
   - `PLATFORMER_KEY_ALIAS`
   - `PLATFORMER_KEY_PASSWORD`
